# Gestão de trabalho e issues

As **GitHub Issues deste repositório** são a fonte canônica para backlog, prioridade, dependências, execução e encerramento do trabalho do conector GLPI Tião.

- Toda mudança acionável deve localizar ou criar uma issue neste repositório.
- Dependências do núcleo devem ser ligadas explicitamente a issues de `itscontrol/tiao-platform`.
- Linear não é obrigatório; referências `TIAO-xxx` existentes são apenas históricas.
- Reclaim, Google Calendar, estimates, cycles e label `reclaim` são opcionais e nunca constituem gate.
- Pull requests, commits e documentação devem referenciar a issue correspondente no GitHub.

A issue deve registrar, na medida aplicável, problema, impacto, critérios de aceite, dependências, riscos, prioridade e responsável. Ao concluir, registrar testes, limitações, documentação, riscos e próximos passos.

Esta política prevalece sobre instruções antigas que exijam ferramentas externas para gerir o trabalho.
